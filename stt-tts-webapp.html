A web app that listens, understands, and talks back

An interactive Speech-to-Text and Text-to-Speech web app built with Flask and PostgreSQL, extended into a small voice assistant that can understand a spoken request and act on it.

Team · 8 members Stack · Flask + PostgreSQL Speech · SpeechRecognition, pyttsx3 / gTTS

Overview

Typing is not always the easiest way to use a website

Not every user finds typing or reading on-screen text easy or convenient. This project started from a simple gap: few lightweight web apps combine Speech-to-Text (STT) and Text-to-Speech (TTS) in one place. The first version is exactly that, a Flask web app where a user can speak, see it turned into text, and hear text read back to them, with every interaction logged to a PostgreSQL database.

The project followed a design-thinking process end to end: define the problem, research the available STT/TTS tools, prototype, test, then finalize a working local build ready to demo.

How it works

From a spoken sentence to a database query and back

The second phase of the project pushed the idea further than simple transcription: a full voice-assistant pipeline that can understand an instruction, not just transcribe it. Speech becomes text (STT), the text is parsed for intent and entities (NLU), that intent becomes a database query, and the query's result is turned back into a spoken sentence (NLG plus TTS).

Technical detail: a worked example

A spoken request like "add a meeting Thursday at 3pm" flows through the pipeline as:

  • STT transcribes the audio to text.
  • NLU extracts an intent (add_schedule) and entities (event, date, time).
  • SQL inserts the new row into the schedule table via psycopg2.
  • NLG composes a confirmation sentence from the result.
  • TTS speaks that sentence back to the user.

A query like "what's my schedule today" follows the same path in reverse: NLU extracts the date, a SQL SELECT retrieves the matching rows, and NLG turns the result set into a spoken summary.

Conclusion

A database turns a voice app into an assistant

The first working version ran locally with a functioning Flask backend, PostgreSQL storage, and a simple, user-friendly interface for voice input and output. Layering NLU and a database on top of basic STT/TTS is what took the project from "transcribe and read back" to something closer to a real voice assistant, one that can act on a request and answer questions about stored data in real time.
